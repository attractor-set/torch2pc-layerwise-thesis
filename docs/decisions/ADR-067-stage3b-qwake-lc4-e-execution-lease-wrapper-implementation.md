# ADR-067: атомарная реализация файла владения и исполняющей обёртки `QW-LC4-E`

[English version](ADR-067-stage3b-qwake-lc4-e-execution-lease-wrapper-implementation_EN.md)

- **Статус:** принят как отдельный срез реализации; фактический захват и [выполнение](../glossary.md#term-execution) запрещены
- **Дата:** 27 июля 2026 года

## Контекст

Проектирование файла владения и исполняющей обёртки слито через PR №127 в
`main` коммитом `e0455dc77b49f5b220231509fe6062d275b6ee9b` и независимо
проверено. Предыдущий срез зафиксировал предварительную запись владения,
привязку к конкретному допуску и контракт эффектов, но намеренно не содержал
программы атомарного захвата, исполнителя или записи результатов.

Следующий кодовый срез должен доказать, что эти эффекты можно реализовать без
ослабления границ:

1. ровно один конкурентный процесс получает файл владения;
2. файл владения остаётся после любой ошибки и запрещает повтор;
3. каталог результата не может быть перезаписан;
4. неполный каталог не становится каноническим результатом;
5. импорт модуля и проверка реализации не создают владение и не запускают
   вычисление в репозитории.

## Решение

Добавить отдельный модуль
`stage3b_qwake_lc4_execution_wrapper_implementation.py`, не изменяя
зафиксированный модуль проектирования и его контрольные суммы.

Реализация содержит следующие эффекты, доступные только через явный вызов:

- атомарную запись временного файла в том же каталоге, `fsync` и
  исключительный захват целевого имени через жёсткую ссылку без замены;
- повторную проверку отсутствия разрешённого каталога результата сразу после
  успешного захвата; если каталог возник в окне гонки, файл владения
  сохраняется, а исполнитель не вызывается;
- загрузку материализованного файла владения с проверкой канонической
  сериализации, хэша, коммита обёртки и записи допуска;
- [запуск](../glossary.md#term-run) внедрённого вычислительного модуля только в одноразовом скрытом каталоге подготовки;
- запрет символических ссылок и нерегулярных файлов в дереве подготовки;
- каноническую квитанцию вычислительного модуля и квитанцию исполняющей обёртки;
- синхронизацию файлов и каталогов и атомарное продвижение результата через
  системный вызов `renameat2(RENAME_NOREPLACE)`;
- удаление неполного каталога подготовки при ошибке при сохранении файла
  владения.

Модуль не импортирует библиотеку вычислительных тензоров или конкретный
модельный исполнитель. Вычислительный модуль передаётся через типизированный
протокол. Это позволяет проверить механику на
синтетическом временном каталоге, не открывая рабочий запуск.

## Проверочная модель

Проверяющая программа выполняет полный синтетический цикл только под `/tmp`:

1. повторно проверяет замороженный допуск;
2. строит тестовую запись владения;
3. атомарно материализует её во временном корне;
4. запускает синтетический вычислительный модуль, который создаёт один инженерный файл;
5. записывает квитанцию и атомарно продвигает временный результат;
6. подтверждает сохранение файла владения;
7. удаляет временный корень;
8. повторно подтверждает отсутствие файла владения и каталога результата в
   репозитории.

Модульные тесты отдельно проверяют конкурентный захват, повторный вызов, существующий
результат, гонку после захвата, повреждённое владение, символическую ссылку,
ошибку вычислительного модуля, неверную квитанцию, пустой результат, гонку перед продвижением
и неизменность чужого каталога результата.

## Последствия

После коммита, слияния и независимой проверки реализации разрешается отдельная
фиксация выполнения. Она должна связать точный коммит реализации, неизменяемый
образ, явное подтверждение оператора и единственный допустимый вызов. Только
эта будущая фиксация может открыть фактический захват. До неё запуск любых
эффектов должен завершаться отказом и не может учитываться как `QW-LC4-E`.
