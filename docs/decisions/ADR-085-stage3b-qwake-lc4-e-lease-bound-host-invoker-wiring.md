# ADR-085: привязка исполнителя хоста к постоянному файлу владения v2

- **Статус:** принято
- **Дата:** 2026-07-30

## Контекст

После ADR-084 репозиторий умеет атомарно записывать постоянный файл владения v2
и устойчивую квитанцию терминального исхода, но исторический исполнитель хоста
остаётся вызываемым без проверки этого файла. Историческую реализацию и её
замороженные идентичности менять нельзя.

## Решение

Добавляется новый единственный перспективный вход
`invoke_lease_bound_host_runtime`. Он:

1. проверяет точные сохранённые байты файла владения v2 до проверки образа и до
   обращения к процессу;
2. делегирует неизменному историческому исполнителю не более одного запуска;
3. вычисляет хеши полных потоков независимо от ограниченного представления;
4. записывает одну устойчивую терминальную квитанцию для успеха, отказа до
   запуска, ошибки создания процесса и ошибки после запуска;
5. запрещает повтор и устойчиво закрывается при существующей квитанции;
6. считает историческую операцию прямого вызова заменённой и требует новой
   будущей авторизации, указывающей на вход, привязанный к файлу владения.

Статический проверяющий модуль разрешает прямой вызов нижнего исполнителя только
в неизменном историческом модуле и в новом модуле привязки. Новые производственные
точки входа с прямым вызовом запрещены.

## Граница эффектов

Этот срез не создаёт рабочий файл владения, не проверяет локальный образ, не
материализует команду и не запускает Docker. Тесты используют только временные
репозитории, поддельный образ и поддельный дочерний процесс.

```text
LEASE_BOUND_HOST_INVOKER_ENFORCED=true
FINAL_EXECUTION_ACKNOWLEDGED=false
ONE_SHOT_ENGINEERING_INVOCATION_PERMITTED=false
EXECUTION_LEASE_MATERIALIZED=false
DURABLE_HOST_OUTCOME_PRESENT=false
AUTHORIZATION_CONSUMED=false
RUNTIME_EXECUTION_PERFORMED=false
DOCKER_RUN_PERFORMED=false
LOCAL_COMPUTE_EXECUTION_OPEN=false
```
