# ADR-090: реализация материализации финального подтверждения `QW-LC4-E`

- **Статус:** принято
- **Дата:** 2026-07-30
- **Область:** `QW-LC4-E`, финальное подтверждение оператора

## Контекст

ADR-089 зафиксировал связанный с оператором контракт будущей материализации и
оставил модуль записи невызванным. PR #150 с этим контрактом слит в `main`
`6497cd904f9403622249c5a32f08ef6e8bb11532` и независимо проверен. Для
следующего этапа нужен узкий программный адаптер между предварительно
сформированной материализацией и уже проверенным атомарным модулем записи, но
сам рабочий вызов должен оставаться отдельным.

## Решение

Добавить отдельный модуль реализации, импорт которого не создаёт побочных
эффектов. Его единственная явно вызываемая функция материализации:

1. повторно проверяет точную зафиксированную цепочку исходных данных и квитанцию
   проверки PR #150 после слияния;
2. принимает только уже валидированный
   `ProspectiveFinalExecutionAcknowledgementMaterialization`;
3. передаёт ровно одну операцию записи существующему
   `persist_final_execution_acknowledgement`;
4. не выполняет прямых операций записи в файловую систему;
5. после записи ровно один раз вызывает проверку точных сохранённых байтов и
   требует полного равенства результатов;
6. не создаёт маркер владения выполнением или долговечную итоговую квитанцию, не
   проверяет образ, не материализует команду, не запускает Docker или среду
   выполнения и не потребляет разрешение;
7. запрещает рабочую точку вызова на текущем этапе и автоматическую повторную
   попытку.

## Граница текущего этапа

Реализация функции материализации присутствует, но не вызывается. Положительные
тесты могут создавать подтверждение только в изолированных временных копиях
минимального репозитория. Реальный рабочий путь, маркер владения выполнением,
итоговая квитанция и среда выполнения остаются отсутствующими.

```text
MATERIALIZATION_AUTHORING_POST_MERGE_VERIFIED=true
ACKNOWLEDGEMENT_MATERIALIZATION_CONTRACT_AUTHORED=true
ACKNOWLEDGEMENT_MATERIALIZATION_IMPLEMENTED=true
MATERIALIZER_CALLED=false
FINAL_EXECUTION_ACKNOWLEDGEMENT_ISSUED=false
FINAL_EXECUTION_ACKNOWLEDGED=false
ONE_SHOT_ENGINEERING_INVOCATION_PERMITTED=false
EXECUTION_LEASE_MATERIALIZED=false
DURABLE_HOST_OUTCOME_PRESENT=false
AUTHORIZATION_CONSUMED=false
RUNTIME_EXECUTION_STARTED=false
RUNTIME_EXECUTION_PERFORMED=false
IMAGE_INSPECTION_PERFORMED=false
INVOCATION_COMMAND_MATERIALIZED=false
DOCKER_RUN_PERFORMED=false
LOCAL_COMPUTE_EXECUTION_OPEN=false
```

## Последствия

После слияния и отдельной проверки может быть открыт самостоятельный этап
фиксации точного вызова, который свяжет конкретные идентификаторы оператора,
издателя и выполняющего материализацию субъекта, а также временные метки.
Слияние ADR-090 само по себе не создаёт подтверждение и не разрешает вызов.
