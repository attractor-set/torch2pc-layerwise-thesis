# ADR-096: реализация производственной точки вызова операторской операции материализации подтверждения

- Статус: принят
- Дата: 2026-08-01
- Решение: реализовать единственный производственный командный интерфейс по контракту ADR-095, не выполняя его в основном рабочем дереве и не открывая разрешение на операцию.

## Контекст

PR №162 был слит как `b27e252cf7c64e88d5d61bf7a23c70ffc5957959` поверх продвинувшегося `main`. Независимая проверка согласованности установила первый родитель `dc8dc200515959858d43b68984dbd87f27f3446c`, исходную базу `23a86cc0769f20b4b7536e64250f3dee062aaa62`, точную разность по первому родителю `18/1516/0` и совпадение дерева автоматического слияния `408c9cbbd97c35292ba8a9476c54d3fe0905f00e`.

ADR-095 зафиксировал путь, символ, явные входы и единственный делегат. До этого среза файл точки вызова отсутствовал.

## Решение

Добавляется единственный файл:

```text
scripts/invoke_stage3b_qwake_lc4_final_execution_acknowledgement_materialization_operation.py
```

Его `main` требует оба явных параметра:

```text
--project-root
--operation-json
```

Файл операции должен быть обычным нессылочным файлом с точным каноническим `JSON` и полным набором полей предварительно сформированной операции. Стандартный ввод, переменные окружения, интерактивные запросы и значения по умолчанию запрещены.

После синтаксической и канонической проверки командный интерфейс вызывает ровно один раз:

```text
torch2pc_thesis.stage3b_qwake_lc4_final_execution_acknowledgement_materialization_invocation_operation_implementation.perform_final_execution_acknowledgement_materialization_invocation_operation
```

Отдельная предварительная проверка устойчивого состояния и прямые обращения к адаптеру, материализатору или модулю записи запрещены. Автоматический и слепой повтор отсутствуют.

Успешный результат дополнительно проверяется на точные признаки операции, единственного вызова, отсутствия повторов и закрытой границы выполнения. Только после этого канонический `JSON` результата выводится в стандартный вывод. Отдельный файл результата не создаётся. Любая ошибка даёт ненулевой код и не выводит частичный результат в стандартный вывод.

## Проверка без рабочего выполнения

Пакет реализации и статический проверяющий модуль импортируют и анализируют точку вызова, но не запускают операцию. Поведенческие тесты либо подменяют единственный делегат, либо выполняют полный путь только в изолированной временной копии репозитория. Основное рабочее дерево не получает подтверждение, файл владения, квитанцию исхода или доказательства выполнения.

Исторические реестры исходных файлов и тесты ADR-094/ADR-095 остаются побайтово неизменными. Общий `tests/conftest.py` создаёт для этих двух исторических модулей изолированное временное представление без точки вызова последующего среза, поэтому прежние утверждения об отсутствии продолжают проверять именно свой замороженный срез, а текущая производственная реализация не подменяется.

## Последствия

Наличие командного интерфейса не является разрешением на его [запуск](../glossary.md#term-run). После слияния допускается только отдельный срез подготовки выполнения точки вызова. Он должен сформировать и отдельно авторизовать канонический файл операции; эта реализация сама по себе не создаёт подтверждение и не потребляет полномочие.
