# ADR-111: неизменяемая коррекция порядка фиксации и выполнения `QW-LC4-E`

- **Статус:** принято для единственного корректирующего PR; исправленный образ и [попытка](../glossary.md#term-attempt) 002 ещё не материализованы
- **Дата:** 2026-08-04
- **Область:** `QW-LC4-E`

## Контекст

Попытка `qwake-lc4-runtime-validation-v1-attempt-001` завершилась терминальным исходом `nonzero_return_code` с кодом `1` после одного запуска дочернего процесса. Неизменяемая квитанция хоста имеет файловый SHA-256 `9004103dd1a54299a8e217422f7b2c36d47f4bca5b9a81dd8f36f99cd9b6cf66` и семантический SHA-256 `649c2a723049e703c3ae1232d18ea9fbde25c393ff4b1047bfb6c5154e608f8f`.

Причина локализована в исторической точке входа. Она сначала атомарно создавала `lease-v1`, а затем вызывала `execute_authorized_runtime`, который повторно проверял условие отсутствия владения до фиксации. Эта повторная проверка закономерно отвергала только что созданный объект. Вычислительный исполнитель и публикация инженерного результата не начинались.

Исторические модули, пакеты и квитанции уже входят в замороженную цепочку [доказательных материалов](../glossary.md#term-evidence). Их изменение или пересчёт задним числом запрещены.

## Решение

Коррекция оформляется как отдельное неизменяемое наложение для будущего исправленного образа. Исторический файл `scripts/run_stage3b_qwake_lc4_authorized_runtime.py` остаётся неизменным на уровне байтов. Пакет коррекции содержит его проверяемую замену и точный файл различий.

Исправленная точка входа выполняет следующий порядок:

1. проверяет материализованную фиксацию [среды исполнения](../glossary.md#term-runtime);
2. проверяет операторское подтверждение;
3. получает один `FrozenAdmissionIdentity` до атомарной фиксации;
4. создаёт исполнитель до необратимой фиксации;
5. строит перспективный объект владения из полученного допуска;
6. атомарно материализует объект владения с тем же допуском;
7. передаёт тот же допуск в `run_claimed_execution_wrapper`.

После фиксации запрещён вызов `verify_unconsumed_frozen_admission`, `claim_execution_lease` или `execute_authorized_runtime`. Атомарность фиксации, запрет перезаписи, повторная проверка материализованного объекта владения и продвижение результата без замены сохраняются существующей реализацией обёртки.

## Граница единственного PR

Исправление выполняется в одной ветке и одном PR. Текущий коммит авторизует только неизменяемое наложение коррекции и его проверки. Он не строит образ, не создаёт попытку 002 и не разрешает [выполнение](../glossary.md#term-execution). Последующие коммиты того же PR должны добавить точную идентичность исправленного образа, отдельную попытку 002 и её новую одноразовую авторизацию. Второй корректирующий PR не допускается.

## Неизменяемость попытки 001

Следующие объекты сохраняются без изменений:

- `attempt-001.execution-lease.json`;
- `attempt-001.execution-lease-v2.json`;
- `attempt-001.host-outcome.json`.

Попытка 001 терминальна. Автоматический или ручной повтор с её идентичностью запрещён.

## Последствия

- исторические замороженные идентичности исходного кода остаются валидными;
- исправление можно проверить до построения образа;
- одна и та же идентичность допуска проходит через построение, материализацию и выполнение;
- новый [запуск](../glossary.md#term-run) среды исполнения возможен только как попытка 002 после отдельного допуска в том же PR;
- `QW-5`, научный сбор данных и публикация остаются закрытыми.
