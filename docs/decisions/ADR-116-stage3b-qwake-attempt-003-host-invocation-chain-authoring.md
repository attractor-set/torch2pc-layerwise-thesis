# ADR-116: подготовка цепочки хост-вызова попытки 003

## Статус

Принято как ограниченная подготовка будущей цепочки хост-вызова. Этот срез
не исполняет и не сохраняет хост-команду.

## Контекст

PR #185 включил точное свидетельство авторизации попытки 003 в `main` коммитом
`e7a0fb92d17bdb9a1165f211db7a1e94ff296999`. Каноническая идентичность
авторизации —
`sha256:46baed5cebc1efe4abf68c21652775eee5c1123df09465d332c151303d890d63`;
она действует, не потреблена и связана с [фиксацией выполнения](../glossary.md#term-execution)
`sha256:82e7509a0d2627f8b91daa34049307da573619b740a2022b72b922edcd07898e`.
Локальный замороженный образ, закреплённая копия Torch2PC и устройства ROCm
уже подтверждены как готовые, но предпусковая проверка корректно запретила
вызов [среды выполнения](../glossary.md#term-runtime), поскольку для попытки 003
отсутствует цепочка хост-вызова.

Исторические записи реализации и связывания источника намеренно сохраняют
`host_invocation_chain_authored=false`: это свидетельство состояния на момент
их подготовки, и переписывать его нельзя.

Точка входа среды выполнения уже необратима на границе аренды: после проверки
фиксации выполнения и авторизации она материализует аренду выполнения до вызова
внутренней среды выполнения. Следовательно, хост-команда не может
импровизироваться во время запуска. Её образ, монтирования, окружение,
устройства, ресурсы и политика безопасности должны быть отдельным точным
контрактом.

## Решение

Добавить чистый модуль цепочки хост-вызова попытки 003, замороженный пакет
подготовки, проверяющий модуль и целевые тесты. Контракт связывается с:

- коммитом `main` после слияния авторизации
  `e7a0fb92d17bdb9a1165f211db7a1e94ff296999`;
- коммитом исходников среды выполнения
  `541b34a57297d2c5a82851bd846b583d4904fba6`;
- Torch2PC `b20d9142e4bdbf57b3ec8bf9f9c4472372ec8db4`;
- замороженным образом
  `torch2pc-layerwise-thesis@sha256:aec2178f1de409143553ccaecb34b2d0e4d19332040fce56742e422f770ef188`;
- закреплённым базовым образом ROCm/PyTorch;
- точными путями результатов, аренды и долговечного исхода попытки 003.

Будущая команда Docker может только конструироваться как данные. Разрешены
ровно три монтирования:

1. `experiments/frozen` -> `/workspace/experiments/frozen`, только для чтения;
2. `external/Torch2PC` -> `/workspace/external/Torch2PC`, только для чтения;
3. `results` -> `/workspace/results`, чтение и запись.

Дерево исходников проекта и [набор данных](../glossary.md#term-dataset) не
монтируются. Используются точный репозиторный дайджест из фиксации выполнения,
отключённая сеть, корневая файловая система только для чтения, запрет новых
привилегий, удаление всех дополнительных возможностей, автоматическое удаление
контейнера, фиксированный рабочий каталог, точные привязки GPU-устройств, явные
`UID`/`GID` и лимиты ресурсов, а также фиксированное окружение с явными привязками
потоков и GPU. Интерпретация оболочкой и наследование окружения запрещены.

Модуль может разобрать заранее полученный `JSON` от `docker image inspect` и
сконструировать точный `argv` команды `docker run` только в памяти. Создание
процесса в нём отсутствует. Конструирование требует точного квитирования аренды
`CLAIM_QWAKE_LC4_ATTEMPT_003_FROM_CORRECTED_EXECUTION_FREEZE`.

## Правило исторического состояния

Этот ADR не переписывает более ранние записи реализации и связывания источника.
Их `host_invocation_chain_authored=false` остаётся истинным утверждением об их
историческом моменте. Новый пакет цепочки хост-вызова является более поздним
слоем, который доказывает переход к подготовленному хост-контракту.

## Граница

Этот срез не потребляет авторизацию, не создаёт аренду или исход, не сохраняет
хост-команду, не строит и не запускает Docker, не создаёт процесс, не вызывает
код [среды выполнения](../glossary.md#term-runtime) или модели, не обращается к
[набору данных](../glossary.md#term-dataset) и не публикует свидетельства.

`runtime_execution_permitted=false` остаётся частью хост-контракта. После
слияния и независимой проверки этого среза требуется отдельная неисполняющая
материализация и предпусковая проверка хост-команды; только затем одноразовый
вызов среды выполнения может стать допустимым.
