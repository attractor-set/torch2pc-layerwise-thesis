# ADR-119: стабилизация процессорного измерения для попытки 004

Нормативные термины:
[попытка](../glossary.md#term-attempt),
[выполнение](../glossary.md#term-execution),
[кандидат](../glossary.md#term-candidate),
[разогрев](../glossary.md#term-warm-up),
[фиксация](../glossary.md#term-freeze) и
[набор данных](../glossary.md#term-dataset).

## Статус

Принято для авторского описания реализации. Исполнение попытки 004 этим
решением не разрешается.

## Контекст

Попытка 003 завершила все 168 сопоставленных ячеек и 28 резервных проб.
Сравнение ответов, проверка состояния генераторов случайных чисел, резервные
пробы и все проверки порядка для ROCm прошли. Итоговая инженерная проверка
осталась отрицательной только для процессорного поля
`compute_primary_time_ns`.

Последующий аудит только для чтения показал, что основное процессорное время
измеряется через `time.process_time_ns()`, тогда как попытка 003 выполнялась с
восемью процессорными потоками. Ретроспективное изменение результата попытки
003 или допустимого отклонения запрещено.

Существующий общий исполнитель уже связан с историческими фиксациями и
разрешениями посредством SHA-256. Поэтому изменение этого файла для новой
попытки также запрещено.

## Решение

Попытка 004 добавляет отдельную обёртку исполнителя матрицы и не меняет общий
исполнитель.

Перед основной матрицей обёртка требует:

- привязку процесса только к CPU 0;
- `OMP_NUM_THREADS=1`;
- `MKL_NUM_THREADS=1`;
- `OPENBLAS_NUM_THREADS=1`;
- `NUMEXPR_NUM_THREADS=1`;
- один внутрооперационный поток PyTorch;
- один межоперационный поток PyTorch.

Затем для каждого из семи процессорных кандидатов последовательно выполняются
две прогревочные сопоставленные ячейки: канонический повтор 2 и канонический
повтор 3. Эти повторы имеют противоположный порядок двух ветвей и не содержат
резервных проб. Полученные прогревочные записи отбрасываются и не входят в
основную матрицу или агрегаты.

После прогрева управление передаётся неизменённому общему исполнителю, который
выполняет исходные 12 измеряемых пар для каждого кандидата. Алгоритмы,
кандидаты, расписание измеряемых пар, основное процессорное время и допустимое
отклонение не меняются.

## Граница

Этот срез только реализует и проверяет отдельную обёртку. Старые фиксации,
разрешения и реестры не изменяются. Docker не запускается, модель не
исполняется, набор данных не читается, разрешение не расходуется и новая
аренда выполнения не создаётся. Научное выполнение остаётся закрытым.
