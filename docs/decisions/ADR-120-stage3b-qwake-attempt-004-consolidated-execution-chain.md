## Решение

После подтверждения канонического `main` новая попытка получает отдельные
контракт, файл владения, сервер измерительной матрицы, точку входа контейнера и
одноразовый процесс запуска на хосте. Исторические идентичности третьей попытки
и `stage3b_qwake_lc4_runtime_backend.py` не изменяются и не используются как
эффекты четвёртой попытки.

Сервер измерительной матрицы по умолчанию использует
`Attempt004CPUStabilizedMatrixExecutor`. Он фиксирует привязку процесса к
логическому процессору `0`, фиксирует внутрипроцессную и межоператорную
параллельность PyTorch значением `1`, выполняет четырнадцать отброшенных
разогревающих ячеек без резервных проб и затем передаёт неизменённую измеряемую
матрицу существующему `BoundedTorchMatrixExecutor`.

## Однократная граница

Операция на хосте выполняет последовательность:

1. проверяет чистый коммит исходного дерева и неизменённые идентичности Torch2PC
   и научного разрешения;
2. строит образ из точного коммита и фиксирует его хэш;
3. материализует новую фиксацию среды выполнения четвёртой попытки;
4. материализует отдельное эффективное и ещё не потреблённое разрешение;
5. сохраняет точный вектор аргументов Docker до создания дочернего процесса;
6. вызывает ровно один дочерний процесс через `subprocess.Popen` с
   `shell=False`;
7. сохраняет устойчивый итог хост-процесса независимо от результата дочернего
   процесса.

После входа в создание дочернего процесса автоматический повтор запрещён.
Файл владения создаётся только внутри точки входа контейнера и является точкой
потребления разрешения.

## Неизменяемые условия

Основные измерения CPU продолжают использовать `time.process_time_ns()`.
Количество измеряемых повторов на кандидата остаётся равным двенадцати.
Допуск проверки позиционного эффекта не меняется. Научное выполнение, доступ к
тестовой выборке и публикация остаются закрыты.

## Граница этой подготовки

Этот ADR и связанный машиночитаемый контракт только создают исполняемую цепочку
четвёртой попытки. В подготовительном коммите Docker не запускается, разрешение
не создаётся, файл владения не материализуется и выполнение не начинается.
