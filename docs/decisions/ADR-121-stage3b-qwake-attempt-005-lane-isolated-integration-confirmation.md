## Статус

Принято до выполнения попытки 005. Выполнение остаётся закрытым до слияния
реализации и выдачи отдельного одноразового разрешения.

## Контекст

Попытка 003 завершила полную инженерную матрицу: пять из семи процессорных
агрегатов не прошли проверку эффекта порядка, тогда как все семь агрегатов ROCm
прошли. Попытка 004 применила к процессу профиль стабилизации CPU: привязку к
CPU 0, один поток PyTorch и библиотек и четырнадцать прогревочных ячеек вне
измеряемой матрицы. После этого все семь процессорных агрегатов прошли, но все
семь агрегатов ROCm не прошли проверку эффекта порядка.

Разложение по полям показало, что регрессия попытки 004 относится к временным
полям ROCm, а не к корректности ответов, состоянию генераторов случайных чисел,
резервным пробам или полноте пар. Следовательно, наблюдения указывают на стабилизацию CPU,
но область действия этого профиля была слишком широкой: процессные ограничения CPU
распространились на канонический канал ROCm.

Текущий контракт требует один полный успешный отчёт по тем же четырнадцати
агрегатам. Посмертное объединение прошедших агрегатов из разных попыток не
допускается.

## Решение

Попытка 005 является единственным перспективным интеграционным подтверждением
с изоляцией каналов по процессам.

Один внешний одноразовый запуск создаёт два внутренних процесса без
автоматического повтора:

1. Процесс CPU выполняет только `cpu_float64_engineering`. Он сохраняет
   подтверждённый профиль попытки 004: привязка к CPU 0, один внутрооперационный
   поток PyTorch, один межоперационный поток PyTorch,
   `OMP/MKL/OPENBLAS/NUMEXPR=1` и прогревочные повторы 2 и 3 для каждого из семи
   кандидатов.
2. Процесс ROCm выполняет только `rocm_float32_canonical`. Он восстанавливает
   канонический профиль управления хостом из попытки 003: CPU 0–7,
   `HIP_VISIBLE_DEVICES=0`, `OMP/MKL/OPENBLAS/NUMEXPR=8`. Перед измеряемой
   матрицей выполняются симметричные прогревочные повторы 2 и 3 для каждого
   кандидата.
3. Оба набора прогревочных ячеек исключаются из измеряемой матрицы и не создают
   резервных проб.
4. Результаты двух процессов собираются в один результат исходной матрицы:
   168 измеряемых ячеек, 28 резервных проб и 14 агрегатов в исходном порядке
   CPU → ROCm.
5. После объединения применяется неизменённая проверка `RuntimeMatrixResult.require()`
   и неизменённые условия `validation_passed`.

## Не изменяется

Не изменяются алгоритмы точной и аналитической ветвей, синтетическая партия,
начальные значения генераторов, 12 измеряемых повторов, чередование порядка
ветвей, основные часы измерения, поля стоимости, резервные пробы, допустимые
отклонения проверки эффекта порядка, критерии ответа и генераторов случайных
чисел, общий исполнитель среды выполнения и научное разрешение.

Межканальное сравнение остаётся запрещённым. Профили CPU и ROCm являются
локальными для своих процессов.

## Критерий завершения

Попытка 005 считается успешной только если единый терминальный отчёт содержит
`validation_passed=true` и все четырнадцать агрегатов проходят исходную
проверку эффекта порядка. Независимо от результата попытка одноразовая и не
повторяется автоматически.

Научное выполнение, доступ к тестовому набору данных и публикация остаются
закрытыми.
