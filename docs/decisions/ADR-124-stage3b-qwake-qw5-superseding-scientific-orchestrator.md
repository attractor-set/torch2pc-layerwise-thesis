## Статус

Принято как подготовка исходного кода замещающего научного оркестратора после
структурной проверки готовности `C1`. Этот срез не строит новый образ, не
заменяет ранее зафиксированный образ `QW-5` и не открывает научную кампанию.

## Причина

После слияния ADR-123 независимая структурная проверка исходного дерева
`4eb23b6f5e2e3b2f3cdee83a4732f8a091b7b662` установила ограничение поверхности
исполнения. Модель возможностей содержит роль `C1_COLLECTION`, компоненты
`A0/A1/A2`, зарегистрированные аналитические компоненты, каноническое завершение
суффикса и постфактум-метки оракула. Однако единственная готовая исполняемая
цепочка `QWake-FP` относится к инженерной проверке, использует
`synthetic-engineering-batch-v1` и материализует `SCIENTIFIC_EVIDENCE=false`.
Заранее зарегистрированной точки запуска научной кампании в образе ADR-123 нет.

Поэтому запрос `C1` нельзя корректно связать с образом
`sha256:800471114a6fec7d401fcbc3c781957265aaa351babaa5adf823d1521a95a8e3`.
Изменять этот образ или его исходное дерево после фиксации запрещено; ADR-123
сохраняется как исторически корректная фиксация `QW-5` версии 1.

## Решение

1. Сохранить образ ADR-123 и корректирующую фиксацию
   `sha256:b435c09c02783f09156cfb7f68045151aa659e144e3c95d85480cee99020f6f4`
   неизменными и не переинтерпретировать их как готовность к `C1`.
2. Добавить общий заранее зарегистрированный оркестратор для ролей
   `C1_COLLECTION`, `C2_CALIBRATION`, `C3_CONFIRMATORY` и `R_REPLICATION`, не
   создавая отдельный исполняемый путь для каждого этапа.
3. Разделить оркестратор на две заранее зарегистрированные части. Хостовая часть
   проверяет точный образ и исходный коммит, атомарно потребляет одноразовое
   разрешение через `host-claim.json` и делает не более одного `docker run`.
   Встроенная часть повторно проверяет запрос, разрешение, идентичность образа,
   манифест исходников и квитанции предшествующих этапов, после чего исполняет
   только закрытый реестр компонентов.
4. Запретить произвольный исполняемый код, команды оболочки, подмену исходников
   через подключаемые каталоги, сеть внутри контейнера, автоматический повтор,
   доступ к тестовой выборке и публикацию.
5. Для живых этапов разрешить только зарегистрированную разделённую выборку и
   точные хэши её файлов; `C2_CALIBRATION` оставить полностью автономным
   относительно живого набора данных.
6. Связывать квитанции предшественников одновременно их семантическим хэшем и
   хэшем байтов файла. Для `C2/C3/R` дополнительно проверять связь квитанции с
   точным запечатанным набором траекторий или зафиксированной политикой.
7. Расширить только чистую схему признаков `QWake-FP`, чтобы зарегистрированные
   наблюдения `A1/A2` могли содержать канонические кортежи и отображения.
   Численные пороги политики остаются допустимыми только для заранее
   зарегистрированных скалярных полей.
8. Не изменять `stage3b_qwake_lc4_bounded.py`. Требуемое для `float32`
   каноническое восстановление избыточного поля ошибки выполняется только в
   новом слое перед вызовом существующего аналитического завершения; профиль
   сравнения `rocm_float32_canonical` и его допуски не меняются.
9. Зафиксировать исполняемое замыкание будущего образа в
   `runtime-SHA256SUMS`. Запрос научной кампании обязан быть связан с точным
   хэшем этого манифеста.
10. В этом срезе не строить и не запускать замещающий образ. После слияния
    требуется отдельная проверка состояния `main`, затем отдельное построение,
    проверка и фиксация нового образа. Только после этой фиксации может быть
    заморожен запрос `C1`.

## Последствия

ADR-123 остаётся неизменяемой исторической фиксацией версии 1, а не ошибочным
научным запуском. Новый исходный код создаёт только исполняемую предпосылку для
будущего замещающего образа. До его отдельной проверки и фиксации запрос `C1`,
научное выполнение, доступ к тестовой выборке и публикация остаются закрытыми.
