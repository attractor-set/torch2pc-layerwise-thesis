# Проверка репозитория

[English version](validation_EN.md)

Проверки выполняются из текущего коммита Git. Статические отчёты с результатами
проверок не хранятся как постоянное утверждение в корне репозитория, поскольку
после изменения исходного кода они перестают описывать текущее состояние.

## Локальная проверка

```bash
source .venv/bin/activate
python3 -m ruff check src tests scripts/*.py
python3 -m mypy src
python3 -m pytest -q
python3 scripts/check_epistemic_language.py
python3 scripts/check_language_structure.py
python3 scripts/check_glossary_usage.py
python3 scripts/check_local_links.py
bash scripts/validate_repository.sh
```

## Проверка в CI

GitHub Actions выполняет те же проверки в чистом окружении с зависимостями,
ограниченными файлами `requirements/lock-dev.txt` и
`requirements/torch-cpu.txt`.

Зелёный CI подтверждает прохождение проверок для конкретного коммита. Он не
подтверждает научные гипотезы и не заменяет Docker/ROCm, C0/C1, пилотное или
итоговое [выполнение](glossary.md#term-execution).

## Сведения о выпуске

Для `v1.0.0` `scripts/check_release_contract.py` проверяет контракт выпуска, а
`scripts/build_release.sh` является сборщиком выпуска. Он проверяет контракт
публичной поверхности, выполняет `make thesis-check` и финальную сборку
диссертации, после чего создаёт:

- архив исходного дерева из `git archive` и его SHA-256;
- финальный PDF и его SHA-256;
- JSON с версией, коммитом и деревом Git;
- `release-manifest.json` с идентичностями артефактов, числом страниц и
  статусами документных проверок;
- примечания к выпуску.

Сборщик требует неизменённого отслеживаемого дерева и индекса, но не считает
локальные неотслеживаемые научные и исполнительные доказательные артефакты
частью публичного исходного пакета выпуска. Он не запускает и не разрешает
научные эксперименты.

Сценарий GitHub для тега `v1.0.0` публикует эти артефакты как выпуск GitHub и
не перезаписывает уже существующий выпуск с тем же тегом.
