\chapter{Воспроизводимость и трассируемость}
\label{app:reproducibility}

\section{Назначение приложения}

Воспроизводимость в этой работе разделяется на два уровня. Первый уровень ---
\emph{воспроизводимость документа}: из конкретного состояния Git-репозитория
проверяются thesis-facing data contracts, детерминированно генерируются таблицы
LaTeX и собирается PDF. Второй уровень --- \emph{научная трассируемость}:
утверждения диссертации связываются с tracked scientific summaries либо с
замороженными идентификаторами sealed evidence. Эти два уровня не следует
смешивать: повторная сборка PDF не является повторным выполнением научного
эксперимента.

\section{Канонический путь сборки документа}

Основной entrypoint репозитория:

\begin{verbatim}
make thesis
\end{verbatim}

Перед XeLaTeX выполняется \code{scripts/build_thesis_assets.py}. Скрипт
валидирует claims contract, QWake C2 thesis-facing summary, SHA-256 bindings
tracked Stage~1/2/3 evidence и выбранные численные агрегаты. Только после
успешной проверки создаются файлы в \code{thesis/generated/}. Эти generated
файлы не коммитятся и не являются самостоятельным scientific evidence.

Проверка data contract без установленного LaTeX выполняется командой:

\begin{verbatim}
make thesis-check
\end{verbatim}

Каноническая CI-сборка дополнительно фиксирует Git commit, Git tree, версии
\texttt{latexmk}, XeLaTeX и Biber, проверяет PDF magic/размер и публикует
SHA-256 конкретного PDF artifact.

\section{Thesis-facing evidence layers}

В документе используются два компактных machine-readable слоя:
\begin{itemize}
  \item \code{thesis/data/core_results_verified_summary.json} --- проекция
    Stage~1/2/3 результатов. Для каждого upstream tracked artifact хранится
    ожидаемый SHA-256, который заново проверяется при сборке;
  \item \code{thesis/data/qwake_c2_verified_summary.json} --- компактное
    представление sealed QWake C2 result и независимо проверенных агрегатов.
    Сборка дополнительно сверяет статусы C08--C11 с frozen selection, best-safe
    aggregate и protocol boundary, не выполняя новую policy evaluation и не
    изменяя cost model. Этот файл явно маркирован как
    \code{not_new_scientific_evidence}.
\end{itemize}

Полная QWake forensic surface намеренно не превращается в обычный dissertation
source tree. Для неё диссертация сохраняет frozen artifact identities,
receipt identities, policy identity и общую identity decision-cost sequence.
Это позволяет проверять, к какому именно sealed result относится текст, не
создавая ложного впечатления, что thesis-facing JSON заменяет исходный corpus.

\section{Границы QWake protocol}

Для QWake C2 зафиксированы следующие protocol facts: policy freeze не
установлен, C3 не открыт, повтор attempt и reuse authorization не разрешены.
Поэтому воспроизводимость диссертации не включает повторное выполнение C2 или
переход к C3. Любой будущий marginal-cost experiment должен иметь новый
estimand, новый protocol и новую evidence chain; он не является продолжением
уже закрытой C2 invocation.

\section{Минимальная проверка полученного PDF}

После успешной сборки конкретный artifact может быть идентифицирован командами:

\begin{verbatim}
pdfinfo thesis/main.pdf
sha256sum thesis/main.pdf
\end{verbatim}

SHA-256 в этом контексте идентифицирует конкретный собранный PDF. Byte-for-byte идентичность PDF между независимыми сборками текущим workflow
не заявляется как отдельный научный результат. Источником содержательной
воспроизводимости остаётся exact Git source вместе с прошедшими data-contract
и provenance gates.

\section{Практическая независимая проверка}

Для независимого чтения и проверки документа достаточно следующей
последовательности:
\begin{enumerate}
  \item checkout конкретного Git commit;
  \item выполнить \texttt{make thesis-check} и убедиться, что claims,
    QWake arithmetic/protocol и core-result bindings проходят;
  \item выполнить epistemic-language checker, используемый CI;
  \item в среде с XeLaTeX/Biber выполнить \texttt{make thesis};
  \item проверить PDF metadata и SHA-256;
  \item для спорного численного утверждения перейти от generated table к
    thesis-facing JSON, затем к указанному upstream artifact или frozen
    scientific identity.
\end{enumerate}

Такой порядок делает путь от текста к evidence явным и одновременно сохраняет
границу между документированием уже завершённого исследования и новым
scientific execution.
